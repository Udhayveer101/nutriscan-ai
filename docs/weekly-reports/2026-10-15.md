## 2. Bugs fixed

1. **Scan analysis broken in production (critical).** Moved all Groq calls to `qwen/qwen3.8-27b`, Groq's current multimodal instruct model, with `reasoning_effort: "none"`. Any stray `<think>` block is stripped from model output. (Commit 2687701.)
2. **One LLM failure meant a failed scan.** `extractIngredientsFromText` now falls back to a deterministic label parser (`parseIngredientsLocally`) when Groq throws or returns nothing.
   - The parser handles nested parentheses, code and percent brackets, and "Contains:" / "May contain" tails.
   - Verified with **no** `GROQ_API_KEY`: the analysis still returns 200 with a full score.
3. **Stacked retries.**
   - The Groq SDK's own 2 retries ran inside our `withRetry` (3 attempts), so one failure meant 9 calls and about 20 s. The SDK now uses `maxRetries: 0` with a 15 s timeout.
   - Deferred explanations now run 3 at a time instead of about 15 at once. The bursts were tripping Groq's per-minute limit and starving the next scan's extraction.
   - One failed explanation no longer stops the rest. (Commit a7e0e6e.)
4. **`/og-image.png` was a 404.** It's now generated at build time by `app/og-image.png/route.tsx` (`next/og`), and the metadata is unchanged.
5. **`/api/scan/upload` returned 500 for a non-multipart body.** It now returns 400.
6. **"Lactobacillus acidophilus" scored MEDIUM** because the chemical-name heuristic matched `\bacid`. Live and probiotic cultures are now whole-food markers.
7. **The privacy page** named "Llama vision"; it now names the current Groq models.

## 3. Ingredients added

### New KB profiles
- **Flavourings (natural & artificial).** LOW concern, LIMITED evidence. This fixes the "Natural Flavors" seed row, which the scanner couldn't resolve.
  - Basis: EU Reg. 1334/2008, FDA 21 CFR 101.22/172.515, and FDA's 2018 delisting of 7 synthetic flavours.
  - Keywords: natural/artificial flavour(ing) in UK and US spellings, nature-identical, spice extract(s).
  - Category `flavouring`, so it counts as one additive toward NOVA but isn't a cosmetic "ultra marker". Bare natural flavour alone gives NOVA 3, as `scoring.ts` documents.
- **Liquorice / Glycyrrhizin (INS 958).** MEDIUM when dominant, LOW otherwise.
  - Basis: SCF 2003 upper limit of 100 mg/day; Reg. 1169/2011 Annex III "contains liquorice" and hypertension warnings.
  - Populations: hypertension, heart or kidney disease, pregnancy.
- **Melatonin (added to food or drink).** HIGH/HIGH/MEDIUM.
  - FDA treats it as an unapproved additive in conventional foods (warning letters 2010–2015). The EU authorises supplement claims only.
  - KB profile only; there's no suitable DB category (see proposals).

## 6. Open bugs and proposals (not changed unattended)

- **Wheat flour** (seed row, unscored). On UK labels it means refined white flour, but adding it to the refined-flour bulk rule would also catch "whole wheat flour", because bulk rules run before whole-food detection. That needs a guarded rule in `scoring.ts`.
- **Coconut oil** (seed row, unscored): it's about 85% saturated fat. Should it be a NOVA-2 culinary fat like butter, or get a saturated-fat concern like palm oil (whose concern is also refining contaminants)?
- **Rapeseed oil** is unscored, while canola falls under the omega-6 bulk rule, whose note doesn't fit either oil. Proposal: a separate "refined oils" rule with accurate notes.
- **Categories:** add "Stimulant/Supplement" (melatonin, caffeine, creatine) and "Processing Aid" categories; caffeine still shows "Flavor Enhancer".
- **Gemini OCR** still uses `gemini-2.5-flash`. It worked today, but check Google's deprecation schedule before it suffers the same silent breakage. See idea 1.
- **`/auth/error`** echoes the raw `?error=` value (auth, carried over).
- **`/onboarding`** renders without a session (auth, carried over).
- **`/favicon.ico`** 404 (cosmetic).
- `check-kb` sub-code warnings (E500/E501) and missing ESLint config (carried over).

## 7. Ideas for next week

1. **Model-health canary.** Add a tiny script or GitHub Action that calls each configured LLM model once a day (Groq text, Groq vision, Gemini) and fails loudly on a 404 or "model decommissioned" response. This outage ran about two months unnoticed.
2. **Synthetic scan monitor.** After every deploy, POST one known label to `/api/analysis` and `/api/scan/upload`, and fail the deploy job if either isn't 200. The Playwright script used this week (paste plus upload flows) could live in `scripts/`.
3. **Show when the fallback parser was used.** Return `extractor: "llm" | "local"` from `/api/analysis` and show a subtle "basic parsing" note, so degraded scans are visible to users and in analytics.
4. **Explanation cache.** Cache explanations per (ingredient, mode) in the DB. Most scans repeat common ingredients (sugar, salt, citric acid), so this would cut Groq calls by an order of magnitude and remove the rate-limit risk.
5. **Liquorice and caffeine "dose" insights.** For glycyrrhizin and caffeine, show the reference limits (100 mg/day glycyrrhizic acid; 400/200 mg caffeine) next to the result, personalised by the onboarding profile (hypertension, pregnancy).
