## 2. Bugs fixed

**Scoring engine (high impact)**
- **E-number matching used substrings, so codes collided.** `lookupAdditive` checked `label.includes("e120")`, which meant:
  - "Polydextrose (E1200)" was scored as **carmine**
  - "Lysozyme (E1105)" as an **azo dye (HIGH)**
  - "E1518" (triacetin) as Brilliant Black BN
  - "E1404" as chlorophyll
  - "E407a" (processed eucheuma seaweed) as carrageenan

  Codes are now parsed as whole tokens (`extractCodes`), most specific first: `E341(i)` tries `e341i`, then `e341`.
- **INS and bracketed codes now resolve.** `INS 330`, `ins330`, "acidity regulator (330)", "emulsifiers (322, 471)" and "raising agent (500(ii))" used to score as unknown. Indian (FSSAI) labels use these forms.
- **"yogurt" was scored as an unrefined free sugar (HIGH when dominant).** The keyword `gur` was a substring of "yogurt". Removed; `jaggery` still covers it.
- **Two Southampton-six dyes were missing.** Quinoline Yellow (E104) and Carmoisine (E122) had DB rows but no KB coverage. They are now in the azo-dye family and in the dye + benzoate hyperactivity interaction.
- **"Indigo Carmine" (E132) was scored as carmine**, via the substring "carmine".
- **Interaction rules used substring matching for E-numbers** (E1105 counted as E110). They now match whole codes.
- **Other misroutes fixed:**
  - "Diacetyl tartaric acid esters of mono- and diglycerides" resolved to plain mono-/diglycerides. Same for the acetylated and citric ester names.
  - "Sulphite ammonia caramel" resolved to sulphites.
  - "glycerol monostearate" resolved to glycerol.
  - "corn sugar gum" (xanthan) and "wood/birch sugar" (xylitol) resolved to sucrose.
  - "trichlorogalactosucrose" (sucralose) resolved to sucrose.
  - "pteroylmonoglutamic acid" (folic acid) resolved to MSG.
  - "polyoxyethylene sorbitan monostearate" resolved to sorbitan esters.
- **Duplicate E-numbers and keywords across profiles removed:** E482 (now CSL only), E315 and "erythorbic acid" (now the erythorbic-acid profile only), E420 (now sorbitol only), "glucose-fructose syrup" (now HFCS only), "sodium sesquicarbonate" (now leavening only).
- **"Fully hydrogenated" oils were scored CRITICAL as trans fat.** Fully hydrogenated oil is saturated fat, not a PHO, and now has its own profile.
- **Seed rows with no KB coverage** went from 49 to 7. The remaining 7 are oils, flours and proteins handled by `BULK_RULES`, plus "natural flavours", which is deliberately left unscored.

**Site**
- The home page "Red 40" card linked to `/ingredients/red-40` (404). It now links to `/ingredients/allura-red`.
- Home preview scores and grades were hardcoded and out of date (Sodium Benzoate showed C 53; the real value is 48 D). Scores now match the seed, and grades are derived with `scoreToGrade`.
- The "How we score" grade table (A 80–89, …) didn't match the code (A ≥ 78, B ≥ 65, C ≥ 50, D ≥ 35). The table is corrected.
- The "A–F" copy is now "A+ to F", matching the grades actually shown.
- The "2,000+ ingredients" claim was wrong (the DB has about 320–350). It now says "300+".
- Added `app/robots.ts`. The sitemap, robots and Open Graph now use `SITE_URL` (`NEXT_PUBLIC_SITE_URL`, falling back to the Vercel domain) and `metadataBase`.
- The privacy page named Google Cloud Vision for OCR. The code uses Gemini, with Groq/Llama vision as a fallback. The page now says so.
- Seed content errors fixed:
  - Acesulfame K: acetoacetamide was described as "chlorine-containing"; it isn't.
  - Allura Red: said it was "banned in Denmark, Belgium, France…". That's a myth; it is EU-approved with a warning label.
  - Aspartame: "WHO EFSA maintain approval" was garbled.
  - Sodium Benzoate: "co-containing products" was garbled.
- Removed bogus seed aliases: "Red 3 (UK)" on carmoisine (it collided with US Red 3 / erythrosine and scored CRITICAL), "E420 variant" on HFCS, and two invented maltodextrin aliases.

- `/ingredients` shows "0 INGREDIENTS FOUND" before hydration.
- `4-Hexylresorcinol` is categorised as an antioxidant although it is an anti-browning agent (no fitting seed category).
- Interaction keyword "cola" matches "chocolate", and "ham" matches "graham". A false positive needs phosphoric acid or nitrite present too, so the risk is low.
- Honey is in `WHOLEFOOD_KEYWORDS`, but WHO counts it as a free sugar. Moving it changes validated scores, so it needs a methodology decision.
- The build requires `GROQ_API_KEY` at import time. Lazy client construction in `lib/vision.ts` would make CI builds work without secrets.

## 7. Ideas for next week

1. **Commit a KB consistency checker** (`scripts/check-kb.ts`) and run it from `validate-scoring.ts`. It would check that:
   - no two profiles share a keyword or E-number
   - every keyword resolves to its own profile
   - every seed row and alias resolves to the same profile as its row name

   That check found most of this week's misroutes in seconds.
2. **Whole-word keyword matching** for short keywords (≤ 5 chars: `msg`, `bha`, `bht`, `ssl`, `agar`, `saib`), so the "gur"/"yogurt" class of bug can't recur.
3. **Nutrition-panel parsing.** Sugar and sodium inputs exist in `evaluateProduct`, but OCR only extracts ingredients. Reading the nutrition table would make the free-sugar and salt dimensions real.
4. **Unmatched-ingredient telemetry.** Log (anonymised) ingredient strings that `lookupAdditive` can't resolve, and use the top misses to drive next week's expansion instead of guessing.
5. **ESLint config and CI.** Add `eslint.config.mjs` with `next/core-web-vitals` and a GitHub Action that runs validate-scoring, tsc and a build with a service Postgres. Then "never commit red" is enforced, not just policy.
