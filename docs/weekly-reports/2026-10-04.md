## 2. Ingredients added

**KB profiles:** 194 → 203 (9 new; 13 existing families extended). **Seed rows:** +34. The local seed went from 348 to 382 ingredients.

### New KB profiles (each with a seed row)
- **Isomaltulose (Palatinose):** a slow-release sugar, MEDIUM when dominant. It used to resolve to *isomalt* (a polyol) through the substring "isomalt"
- **Tagatose:** JECFA ADI not specified (2004); EU novel food (2005)
- **Soluble fibre dextrins:** resistant dextrin/maltodextrin, soluble corn/tapioca/wheat fibre, wheat dextrin. FDA counts them as dietary fibre (2018)
- **Added plant fibres:** citrus, oat, bamboo, pea, apple, sugar-beet, potato and wheat fibre (seed row: Citrus Fibre)
- **Cultured fermentates:** cultured dextrose/sugar/wheat flour, fermented wheat flour. These used to be scored as *free sugar* (dextrose/sucrose); they are clean-label propionate preservatives used at trace levels
- **Plant sterols & stanols, E499:** EFSA 2012 opinion. The EU's mandatory warning for pregnant or breastfeeding women and under-5s is in `populations`
- **Soybean hemicellulose, E426:** EFSA 2017, no numerical ADI; soy-allergen note
- **Polyvinylpyrrolidones, E1201/E1202:** EFSA 2020, no ADI needed
- **Supplement coating polymers:** polyvinyl alcohol E1203, methacrylate copolymers E1205/E1206/E1208, PVA-PEG E1209, PEG E1521 (JECFA ADI 10 mg/kg)

### Families extended (one profile per family, not per salt)
- Beta-apo-8'-carotenal **E160e**, added to beta-carotene (EFSA ADI 0.3 mg/kg, revised 2014)
- Tocopherols: **E308, E309**
- Phosphates: magnesium phosphates **E343**
- Tartrates: metatartaric acid **E353**
- Adipates: **E356, E357**
- Gum arabic: OSA-modified gum arabic **E423** (Reg. (EU) 817/2013)
- Aluminium additives: potassium alum **E522**
- Glutamates: monoammonium glutamate **E624**
- Packaging gases: butane, isobutane and propane **E943a/E943b/E944**, by code (plus the keyword "isobutane"). Plain "butane"/"propane" were left out on purpose because they would hijack "1,3-propanediol"
- Nitrites: **"cultured celery"** and "saltpetre". Celery-powder "uncured" bacon now scores the same as nitrite-cured bacon (12/F) and triggers the nitrosamine interaction. Plain "celery powder" stays unscored, so seasonings aren't penalised
- Free sugars: muscovado, demerara, turbinado and piloncillo (unrefined sugars); isoglucose and fructose-glucose syrup (HFCS)
- Prebiotics: galacto-oligosaccharides (GOS), added to the inulin family
- Locust bean gum: "carob bean gum" used to resolve to the *whole-food* list through the word "bean"

### Seed rows for existing families that had none
These now have DB rows: calcium benzoate E213, calcium sulphite E226, potassium bisulphite E228, potassium nitrite E249, potassium nitrate E252, sodium malate E350, calcium malate E352, potassium alginate E402, calcium alginate E404, sorbitan tristearate E492, sorbitan monolaurate E493, aluminium sulphate E520. Isobutane (E943b) also got a row.

### Aliases
- Every new code is in both `E###` and `INS ###` form
- Label names: "Palatinose", "potash alum", "crospovidone", "povidone", "macrogol", "apocarotenal", "Span 20/65", "saltpetre", "soluble corn fibre", "cultured sugar", "fermented wheat flour", "soy polysaccharide"
- Every alias was verified to resolve via `lookupAdditive` to the same profile as its row. Aliases that couldn't resolve safely (PVP, PEG, GOS, "alum") were dropped rather than given short keywords
- One alias was rejected because it would have hijacked another profile: "oligogalactose" contains "lactose"

## 3. Bugs fixed

1. **Interaction keywords matched inside words.** "cola" matched "chocolate" and "ham" matched "graham" (an open bug from last week). Keywords now have to start at a word boundary. Self-checks cover graham/chocolate (no hit) and "Coca-Cola" (still a hit).
2. **Ingredient search missed aliases unless the case matched exactly.** Postgres `has` is case-sensitive, so "palatinose" didn't find the "Palatinose" alias. The search now tries the common casings. Codes typed as "E 211", "INS 330" or "ins1201" are normalised to `E211` form. Verified locally: every one of these now returns its ingredient.
3. **`/ingredients` showed "0 INGREDIENTS FOUND" before the first fetch** (open last week). It now shows "Searching..." until results arrive.
4. **Ingredient search race:** a slow, older response could overwrite newer results. Stale responses are now ignored, and fetch errors no longer escape as unhandled rejections.
5. **Accessibility:** the search input got an `aria-label`, the clear (×) button now says "Clear search", and the Filter toggle exposes `aria-expanded`.
6. **KB misroutes**, fixed through the ingredient work above: isomaltulose → isomalt, cultured dextrose → dextrose (scored as sugar), carob bean gum → whole food, resistant dextrin → modified starch.

**New guardrail:** `scripts/check-kb.ts`, last week's idea #1. It fails when two profiles share a keyword or E-number, or when a profile's own keyword resolves elsewhere. It also warns when a seed row's name and E-number resolve to different profiles. It's added to the CLAUDE.md gate list. It caught one collision this week (a "phycocyanin" duplicate), which was fixed before commit.

  - E500: "Sodium Carbonate" → food-alkalis, but the bare code → leavening-bicarbonates.
  - E501: the same issue the other way round.
  - E420: "Sorbitol Syrup" → polyol-syrups, but the code → sorbitol.

  All of these are LOW-concern pairs, so scores aren't affected. The proper fix is subcode-aware E500(i)/(ii) handling.
- The `glucose-syrup` seed row has the alias "glucose-fructose syrup", but the KB routes that phrase to HFCS. Both are free sugars; the alias should move to the HFCS row.
- Honey is still in `WHOLEFOOD_KEYWORDS` (WHO counts it as a free sugar). This needs a methodology decision.
- The build still needs `GROQ_API_KEY` at import time; a lazy client in `lib/vision.ts` would fix it.

## 7. Ideas for next week

1. **Fix the production-check blind spot.** Allow the production host in the environment's network policy, or add a tiny GitHub Action that curls the key routes after each deploy and posts the status table. Two weeks running, this maintainer has had no view of production.
2. **Seed sync on deploy.** Run an idempotent `prisma db seed` (it already upserts) as a post-deploy step or Vercel build hook, so new ingredient rows reach production without a manual step.
3. **Search ranking.** Exact name, alias and E-number matches should rank above `contains` matches. Today "E330" or "salt" returns alphabetical noise before the exact hit. A `pg_trgm` similarity order, or a two-pass query, would make search feel much smarter.
4. **Unmatched-ingredient telemetry** (carried over). Log anonymised strings that `lookupAdditive` can't resolve, so the weekly expansion targets real misses. This week's misroutes (isomaltulose, cultured dextrose, carob bean gum) were only found by manual probing.
5. **Show "clean-label" equivalence in results.** When a product uses cultured celery or a cultured fermentate, explain that it is chemically the same as the E-numbered preservative it replaces. This is a high-value, myth-busting insight for users.
